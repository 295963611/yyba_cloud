## 1. 概述

### 1.1 背景

悠悠爸家庭云盘已具备个人相册（`photos/`）、个人视频（`videos/`）、音频、网盘与家庭分享能力。用户上传的电影、剧集若混入个人视频，难以浏览，大屏体验差，缺少海报与分类。

### 1.2 产品目标

在现有家庭云盘之上增加 **家庭影院** 能力：

- 云端固定目录存放长片与剧集（`media/movie`、`media/tv`）
- **服务端刮削** 海报与元数据，统一媒体库 API
- **手机**：底部新增「影音」，进入电影海报墙与分类（非 App 主屏）
- **TV**：家庭娱乐主屏，默认电影海报墙 + 分类，兼展示相册/视频/音乐
- **Web**：刮削配置、扫描管理、海报墙预览

### 1.3 一句话定义

**家庭影院 = 固定目录 + 服务端刮削 + 统一媒体库 API + 三端差异化展示；刮削在服务端，端上只读展示与播放。**

### 1.4 与现有能力边界

| 模块 | 云端路径 | 用途 | 是否走刮削器 |
|------|----------|------|--------------|
| 个人相册 | `photos/` | 手机同步照片 | 否（现有相册） |
| 个人视频 | `videos/` | 手机短视频、家庭录像 | 否（现有视频 Tab） |
| 音频 | `audio/`、`uploads/audio/` | 音乐 | 否（现有逻辑） |
| **电影** | `media/movie/` | 长片 | **是** |
| **电视剧** | `media/tv/` | 剧集 | **是** |

个人相册/视频 **不合并** 进影院库；用户应将电影/剧集放入 `media/` 下对应目录。

## 3. 云端目录规范

在用户存储根目录下约定：

```
{username}/
  media/
    movie/              # 电影：单文件或「电影名」文件夹
      阿凡达.Avatar.2009.1080p.mkv
    tv/                 # 剧集：按剧名分文件夹
      庆余年/
        Season 01/
          S01E01.mkv
```

### 3.1 验收标准（P0）

- [ ] 首次启用或新用户自动创建 `media/movie`、`media/tv`（空目录即可）
- [ ] 网盘 / Web 可浏览、上传、删除该目录下文件
- [ ] `media/` 内容 **不进入** 现有相册、个人视频列表
- [ ] 删除走现有回收站；恢复后元数据与文件一并恢复；永久删除清理元数据与 **本地海报文件**（见 §4.5）

## 4. 服务端刮削器（核心，P0）

### 4.1 职责原则

| 层级 | 做什么 | 不做什么 |
|------|--------|----------|
| **服务端** | 扫描、解析文件名、调用刮削源、元数据入库、海报下载缓存、任务队列、对外 API | — |
| Web | 展示、触发扫描/重刮削、TMDb 等配置 | 本地刮削、直连 TMDb |
| 手机「影音」 | 分类列表、海报墙、播放 | 刮削、改元数据 |
| TV | 海报墙、分类、播放 | 刮削、文件管理 |

### 4.2 扫描范围

仅处理：

- `media/movie/**` → 电影库
- `media/tv/**` → 剧集库

### 4.3 识别规则（优先级）

**电影**

1. 文件名/文件夹名（标题、年份，如 `阿凡达.Avatar.2009.1080p.mkv`）
2. 同目录 `.nfo`（若存在）
3. 失败：保留文件记录，刮削状态失败，展示文件名 + 占位图

**剧集**

1. 目录结构（剧名 / Season xx / S01E01）
2. 文件名集号规则
3. `.nfo`
4. 失败：按剧名 + 集号展示

### 4.4 刮削源（MVP）

| 源 | 用途 | 配置 |
|----|------|------|
| TMDb（推荐） | 海报、简介、类型、演职员 | Web 设置 API Key、语言（zh-CN 优先） |
| 本地 NFO | 失败兜底或用户自带 | 解析标准 NFO 字段 |

无外网 / 无 Key：文件仍入库，刮削失败，列表用占位图 + 文件名。

### 4.5 海报本地存储（产品定稿）

**结论：刮削得到的海报、剧照等封面图必须下载到服务端本地，存入独立目录持久化；各端只访问本服务 HTTP 地址，不直连 TMDb 图床。**

#### 4.5.1 为什么必须落盘

| 收益 | 说明 |
|------|------|
| 加载稳定 | 海报墙首屏不依赖外网与 TMDb CDN |
| 内网可用 | 家庭局域网 TV / 手机均可秒开海报 |
| 权限统一 | 与现有 JWT / 登录态一致，不暴露第三方 URL |
| 可维护 | 重刮削可替换本地文件；删除影片可清理对应海报 |

**不做**：仅在元数据里保存 TMDb 图片 URL，由客户端每次拉外网图（仅作 P2 降级备选）。

#### 4.5.2 目录规范（storage 根目录下）

与用户媒资 `media/`、相册缩略图 `.thumbs/` **分离**，建议统一放在 `.media/` 下（系统目录，不参与网盘列表与磁盘索引扫描，规则同 `.thumbs`、`.trash`）：

```
{storage_root}/
  .media/
    posters/
      {username}/
        movie/
          {id}.jpg          # 电影海报（竖版，列表/网格）
        tv/
          {id}.jpg          # 剧集海报（剧级）
        backdrop/
          movie/{id}.jpg    # 电影背景图（横版，详情页 P1）
          tv/{id}.jpg       # 剧集背景图（P1）
```

- `{id}`：优先 TMDb id（如 `movie-19995.jpg`）；无外部 id 时用稳定哈希（如 `hash_{sha8}.jpg`），与媒体元数据表 `poster_path` 字段对应。
- 格式：MVP 统一 JPEG；体积过大时刮削阶段缩放（如海报宽 500px，背景宽 1280px）。
- **不**把海报放进 `media/movie` 用户目录，避免与片源混在一起、误删难维护。

#### 4.5.3 刮削与落盘流程

```
TMDb/NFO 匹配成功
  → 下载 poster URL（及 P1 backdrop）
  → 写入 .media/posters/{username}/...
  → 元数据表记录 poster_path / backdrop_path（相对 storage 根路径）
  → API 返回本服务海报地址（如 /api/cinema/posters/... 或复用 thumbnail 风格接口）
```

- 重刮削：若元数据变更或强制重刮，**覆盖或替换**同 id 文件，并更新库内路径。
- 刮削失败：不写海报文件，列表用 **内置占位图**。

#### 4.5.4 生命周期

| 事件 | 海报文件 |
|------|----------|
| 影片进回收站 | 保留本地海报（列表不展示即可，恢复后仍可用） |
| 永久删除 | **删除**对应 poster/backdrop 文件 + 清元数据路径 |
| 用户删账号 / 清库（P2） | 删除该用户整个 `.media/posters/{username}/` |
| 灾备 | 海报目录随 storage 根一并备份（可选策略，P2） |

#### 4.5.5 验收标准（P0）

- [ ] 刮削成功后，磁盘上存在对应 `.media/posters/` 文件，元数据 `poster_path` 有值
- [ ] 手机 / Web / TV 海报墙 **仅请求本服务 URL**，无外网图床请求
- [ ] 网盘文件列表、sync-index **不出现** `.media/` 目录
- [ ] 永久删除影片后，对应海报文件不存在（或孤儿清理任务可扫出）
- [ ] 无外网时：已落盘海报仍可展示；未刮削项显示占位图

#### 4.5.6 与相册缩略图的关系

| 目录 | 用途 |
|------|------|
| `.thumbs/{username}/` | 相册照片缩略图（现有） |
| `.media/posters/{username}/` | **影院海报/剧照（本需求）** |

二者分离，避免混用路径与清理逻辑。

### 4.6 元数据入库（建议独立媒体表）

与网盘 `files` 通过 `relative_path` 关联，**不混入** 相册 sync-index。

**电影字段（示例）**：标题、原标题、年份、简介、类型列表、地区、时长、评分（可选）、`poster_path`、`backdrop_path`（P1）、刮削状态、刮削时间、external_id（TMDb id）

**剧集字段（示例）**：剧名、季号、集号、集标题、简介、`poster_path`、剧/季/集层级

元数据仅存 **相对 storage 根的路径**（如 `.media/posters/user1/movie/movie-19995.jpg`），不存外网 URL 作为主展示源。

### 4.7 任务触发

| 方式 | 说明 |
|------|------|
| 上传完成 | `media/movie`、`media/tv` 合并上传后异步刮削 |
| 手动扫描 | Web「扫描媒体库」「重刮削本条」 |
| 定时（P1） | 可配置低峰增量/全量扫描 |

### 4.8 刮削验收标准（P0）

- [ ] 后台队列执行，不阻塞上传与播放 API
- [ ] 同一 `relative_path` 重复扫描为更新而非重复插入
- [ ] 进回收站：列表不可见；恢复后可见
- [ ] 永久删除：元数据与 **`.media/posters` 下对应海报文件** 一并清理
- [ ] 失败可记录原因（无匹配、网络、Key 无效），Web 可查看

### 4.9 非功能

- 单用户约 500 部电影量级可浏览；队列并发可配置（如 2～4）
- TMDb API Key 仅存服务端，客户端不可见
- 遵守 TMDb 使用条款；内容由用户自备，产品不提供资源

## 5. 服务端 API（各端只读，示意）

播放继续使用现有 **`/media/file?path=`**（支持 Range）。

| 接口 | 用途 |
|------|------|
| `GET /api/cinema/movies?category=&page=` | 电影列表（按分类） |
| `GET /api/cinema/movies/categories` | 分类列表 |
| `GET /api/cinema/movies/{id}` | 电影详情 |
| `GET /api/cinema/shows` | 剧集（剧名）列表 |
| `GET /api/cinema/shows/{id}/seasons` | 季列表 |
| `GET /api/cinema/shows/{id}/episodes` | 集列表 |
| `GET /api/cinema/posters/...` | 读取 **本地** `.media/posters/` 文件（鉴权同媒体库） |
| `POST /api/cinema/scan` | 触发扫描（Web 管理员） |
| `GET/PUT /api/cinema/config` | TMDb Key、语言等（Web） |
| `GET/PUT /api/cinema/progress`（P1） | 续播进度 |

建议新增 `file_type`：`MOVIE` / `TV_EPISODE`（或与 `VIDEO` 分离），仅 `media/` 路径纳入影院库。

### 6.2 P1

- 家庭共享与影院内容联动（若分享策略扩展）

## 7. 手机端（Android）

### 7.1 定位

云盘与同步为主；**电影不是主类**。影院通过 **底部独立 Tab** 进入。

### 7.2 入口

- 底部导航 **新增「影音」**（图标与首页、网盘区分）
- **不** 将电影海报墙设为 App 启动首页
- 首页相册 / 视频 Tab 保持现状

### 7.3 「影音」内结构

```
底部 [影音]
  ├─ 子 Tab：电影 | 电视剧（默认电影）
  │
  ├─ 电影
  │    ├─ 分类（横向 Chip）：全部 | 最近添加 | 类型…
  │    └─ 海报墙网格 → 详情 → 全屏播放
  │
  └─ 电视剧
       └─ 剧名海报墙 → 详情 → 季 → 集 → 播放
```

### 7.4 电影分类（与 TV、API 一致）

| 分类 | 优先级 |
|------|--------|
| 全部 | P0 |
| 最近添加 | P0 |
| 类型（动作/喜剧/科幻…） | P0 |
| 继续观看 | P1 |
| 年代、地区 | P1 |

### 7.5 验收标准（P0）

- [ ] 底部「影音」Tab 可见且可切换
- [ ] 进入后默认电影海报墙 + 分类
- [ ] 电视剧子 Tab 完整选集播放
- [ ] 数据仅来自 cinema API，不进相册/个人视频
- [ ] 播放复用现有云端视频能力（JWT、`/media/file`）
- [ ] 空状态提示：将文件放入 `media/movie`、`media/tv`

### 7.6 P1

- 继续观看、搜索、详情页演职员
- 影音内 **不上传**；上传指引跳转网盘 `media/`

## 8. TV 端（Android TV / Leanback）

### 8.1 定位

**家庭娱乐展示端**：不做网盘管理，不做上传删除；像家庭影院遥控器。

### 8.2 与手机差异

| 维度 | 手机 | TV |
|------|------|-----|
| 首屏 | 现有首页 | **默认电影海报墙** |
| 电影入口 | 底部「影音」 | 启动即电影 + 分类 |
| 管理 | 网盘 + Web | 无 |

### 8.3 主导航（建议）

```
[ 电影 ]  [ 电视剧 ]  [ 相册 ]  [ 视频 ]  [ 音乐 ]  [ 家庭 ]
   ↑ 默认选中
```

- **电影**：大海报横向墙 + **分类**（全部、最近、类型、继续观看 P1）
- **电视剧**：剧名海报墙 → 季 → 集
- **相册 / 视频 / 音乐**：各模块浏览播放（复用现有云端媒体，展示层统一暗色影院风格）
- **家庭**：家庭共享内容（P1）

### 8.4 电影 Tab 交互（遥控器）

1. 进入 App（已登录）→ **电影海报墙**（默认分类「全部」或「最近添加」）
2. 切换分类行（横 Tab 或侧栏，待 UI 定稿）
3. 左右移动海报焦点 → 确认 → 详情 → 播放
4. 全程 D-pad，返回键层级正确

### 8.5 验收标准（P0）

- [ ] 冷启动默认电影海报墙（有缓存时 3 秒内出图）
- [ ] 电影分类至少：全部、最近添加、按类型
- [ ] 电视剧、相册、视频、音乐可浏览播放
- [ ] 无上传、删除、网盘目录树
- [ ] 登录：服务器 + 账号（与手机一致）

### 8.6 P1

- 首页「继续观看」一行
- 标题搜索
- 海报弱网缓存

## 9. 跨端一致性

| 能力 | 服务端 | 手机影音 | TV |
|------|--------|----------|-----|
| 电影列表/分类 | cinema API | 底部影音 | 默认首屏 |
| 剧集结构 | cinema API | 影音子 Tab | 主导航电视剧 |
| 海报 | **服务端下载至 `.media/posters/`** | 网格 | 大海报墙 |
| 刮削 | 服务端 | 无 | 无 |
| 播放 | `/media/file` | 同 | 同 ExoPlayer |
| 续播（P1） | progress API | 影音内 | 首页一行 |

## 10. 用户旅程

### 10.1 管理员（上传与刮削）

```
Web/网盘上传至 media/movie 或 media/tv
  → 服务端自动或手动扫描
  → 刮削入库 + 海报缓存
  → Web 预览海报墙确认
```

### 10.2 家庭成员（手机）

```
打开 App → 底部「影音」
  → 电影海报墙（选分类）
  → 详情 → 全屏播放
或 → 子 Tab「电视剧」→ 选剧季集 → 播放
```

### 10.3 家庭成员（TV）

```
打开 TV App → 电影海报墙（默认）
  → 切换分类 → 选片 → 播放
或 → 导航至电视剧/相册/视频/音乐
```

## 11. 分期规划

| 阶段 | 服务端 | Web | 手机 | TV |
|------|--------|-----|------|-----|
| **Phase 1** | 目录约定、`media` 表、扫描、TMDb 电影+剧集、海报缓存、cinema 列表/分类 API | 配置、扫描、海报预览 | 底部「影音」P0 | 可选：同 API 验证 |
| **Phase 2** | NFO、续播 progress、定时扫描 | 搜索、续播 | 继续观看、搜索 | 继续观看、搜索 |
| **Phase 3** | 演职员、多源降级 | 详情增强 | 详情增强 | 儿童模式等 |

建议：**Phase 1 服务端 + Web + 手机影音** 先闭环；TV 在 API 稳定后并行（Phase 1 末或 Phase 2 初）。
