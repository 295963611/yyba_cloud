## 1. 需求背景

### 1.1 用户痛点

用户在 Android「我的照片」中，从云端下载一张照片到本地后，列表里会出现 **两条** 记录：

- 一条标记为 **已同步**
- 一条标记为 **未同步**

用户期望：**同一张云端照片，本地只应出现一条**，且该条与云端路径建立明确关联，状态为「已同步」；云端「仅云端」条目应消失。

### 1.2 核心诉求（一句话）

> **下载 ≠ 再存一份新文件；下载 = 把「仅云端」合并为「已关联的本地一条」。**

### 1.3 竞品对标

| 产品 | 下载行为 | 本地与云端关系 |
|------|----------|----------------|
| **Google 相册** | 「保存到设备」写入本地相册，云端项仍保留；列表按「设备/云端」视图区分，同一时刻不混排两条 | 元数据关联，非简单复制两份进同一列表 |
| **iCloud 照片** | 优化存储时本地为缩略图，全分辨率按需下载；已下载与云端为同一 logical asset | 强关联，相册只显示一张 |
| **OneDrive** | 「脱机可用」在原文件上打标记，不另存副本 | 单文件双状态 |
| **百度网盘** | 下载到指定文件夹，网盘列表与本地文件夹分离展示 | 列表不合并，用户不易混淆 |

**本产品定位**：家庭云盘强调「我的照片 = 本地 + 云端合并视图」。应对标 **iCloud / Google 的「一张图一个身份」**，而非百度网盘的「网盘列表 + 下载目录」分离模式。

## 2. 现状与根因（问题分析）

### 2.1 当前设计意图

代码注释已写明目标：下载后写入 `SyncRecord`，移除「仅云端」行，合并为一条「已同步」本地记录。

### 2.2 仍出现两条的原因（按可能性排序）

| 序号 | 根因 | 用户可见现象 |
|------|------|--------------|
| **R1** | 下载总在 `Pictures/悠悠爸云盘/...` **新建物理文件**，不检测设备上是否已有同内容/同云端路径的本地文件 | 原图（相机相册）显示 **未同步** + 新下载副本显示 **已同步** |
| **R2** | 同步判断 `isSyncedFast` 对无 `SyncRecord` 的本地项，用 **按日期拼出来的假路径**（`photos/yyyy/MM/文件名`）去对服务端索引；与真实云端路径不一致则判为 **未同步** | 同一张已下载文件，刷新后变 **未同步**，与内存中 **已同步** 行并存 |
| **R3** | 列表合并时按 `remotePath` 去重，**未按 `localUri` / `fileHash` 去重**；分页重载可能重复插入 | 同 URI 或同云端路径出现两行、状态不同 |
| **R4** | `SyncRecord.modifiedAt` 与 MediaStore 扫描值不一致时，即使有记录也判未同步 | 已绑定记录失效，显示 **未同步** |

### 2.3 数据关联模型（现状）

| 字段 | 含义 |
|------|------|
| `SyncRecord.localUri` | 本地 MediaStore URI（主键级关联） |
| `SyncRecord.remotePath` | 云端真实路径，如 `photos/2023/04/IMG_001.jpg` |
| `SyncRecord.fileHash` | SHA-256，可用于内容级去重 |
| 无 `cloudId` | 以 `remotePath` + `fileHash` 作为云端身份 |

**缺口**：关联是「每个本地 URI 一条记录」，未约束「每个 `remotePath` 只允许一个本地代表」。

## 3. 产品目标

### 3.1 目标

1. 用户对云端照片执行「下载到本地」后，**「我的照片」中该照片只显示 1 条**，状态为 **已同步**。
2. 原「仅云端」条目 **立即消失**，刷新后不再出现。
3. 若设备上 **已存在** 与云端同内容的照片，应 **关联已有文件**，而非再写一份副本（在可识别前提下）。
4. 首页「未同步」计数不因下载而 **虚增**。

### 3.2 非目标（本期不做）

- Web 端下载到浏览器（行为不同，另立需求）
- 双向冲突合并（本地与云端同时修改同一文件）
- 自动删除用户相机相册里的原图（仅关联，不删用户文件）

## 5. 功能定义

### 5.1 下载前检查（P0）

**路径**：用户点击「下载」→ 执行写入前

| 检查项 | 行为 |
|--------|------|
| 是否已有 `SyncRecord.remotePath == 目标云端路径` | 若已有且本地文件仍在 → **不重复下载**，Toast「已在本地」，移除「仅云端」行 |
| 是否已有本地文件 `fileHash` 相同（可选扫描范围：相册 + `悠悠爸云盘` 目录） | 提示「检测到本地已有相同照片，是否关联？」默认 **关联已有**，不新建文件 |
| 用户相机相册中已有同名同大小（弱匹配） | P1：提示关联；P0 至少不因弱匹配自动再存一份 |

### 5.2 下载与绑定（P0）

| 步骤 | 规则 |
|------|------|
| 写入 | 仅当无已有可关联文件时，写入 `Pictures/悠悠爸云盘/{云端相对路径}` |
| 绑定 | 写入/关联后创建或更新 **唯一** `SyncRecord`：`localUri` + `remotePath` + `fileHash` + `modifiedAt` |
| 唯一性 | **每个 `remotePath` 最多一条有效 `SyncRecord`**；新关联时作废旧记录 |
| 列表 | 立即：`removeCloudRowsWithPath` + 插入一条 `synced=true` 的本地行 |

### 5.3 同步状态判定（P0）

判定为 **已同步** 的条件（满足其一即可）：

1. `localUri` 在 `SyncRecord` 中，且 `record.remotePath` 在服务端索引内，且 `modifiedAt` 一致或记录为「下载绑定」（允许下载后一次校正 `modifiedAt`）
2. `localUri` 对应 `SyncRecord.fileHash` 与服务端该 `remotePath` 的 hash 一致

**禁止**：仅凭 `buildRemotePath(本地修改时间)` 拼出的假路径判断同步（仅作无记录时的兜底，且不能与已有 `SyncRecord.remotePath` 冲突）。

### 5.4 列表去重（P0）

构建「我的照片」列表时：

| 去重键 | 规则 |
|--------|------|
| `remotePath` | 同一云端路径只保留一行；优先保留 **有 `localUri` 且 synced** 的行 |
| `localUri` | 同一 URI 不得出现两次 |
| `fileHash`（P1） | 同一 hash 且同一 `remotePath` 只保留一行 |

「仅云端」行：若 `remotePath` 已在 `localRemotePaths` 或存在有效 `SyncRecord`，**不得展示**。

### 5.5 用户操作路径（User Journey）

```
我的照片 Tab
  → 看到「仅云端」照片（云图标）
  → 长按 / 预览页点击「下载」
  → [有本地同 hash] 弹窗：关联已有 / 仍要另存（默认关联)
  → [无重复] 保存到 悠悠爸云盘/... + 写入 SyncRecord
  → 列表：仅云端行消失，出现 1 条「已同步」
  → 下拉刷新：仍为 1 条「已同步」
  → 系统相册：仅 1 个新文件（或 0 个若关联已有）
```

## 6. 验收标准（Acceptance Criteria）

### AC-01 基本下载合并（P0）

- **Given** 列表中存在一条「仅云端」照片 `photos/A/B.jpg`，本地无对应 `SyncRecord`
- **When** 用户下载该照片
- **Then** 列表中该照片 **仅 1 条**，标记 **已同步**；**无**「仅云端」行；**无**额外「未同步」行

### AC-02 刷新持久化（P0）

- **When** 下载成功后下拉刷新或重启 App
- **Then** 仍满足 AC-01

### AC-03 不重复下载（P0）

- **Given** 该 `remotePath` 已绑定有效 `SyncRecord`
- **When** 用户再次点击下载
- **Then** Toast「已在本地」；**不**产生新文件；列表仍 1 条

### AC-04 本地已有同内容（P0）

- **Given** 用户相机相册已有与云端同 hash 的照片（未同步）
- **When** 从云端下载同一张
- **Then** 默认 **关联已有照片** 为已同步，**不**在 `悠悠爸云盘` 再生成副本；列表最终 **1 条已同步**（不应同时出现 1 未同步 + 1 已同步）

### AC-05 未同步计数（P1）

- **When** 完成 AC-01 或 AC-04
- **Then** 首页未同步照片数 **不增加**

### AC-06 视频 Tab 同规则（P1）

- 视频「仅云端」下载后满足与照片相同的「一条 + 已同步」规则

## 7. 边界与异常

| 场景 | 期望行为 |
|------|----------|
| 下载中断 | 无 `SyncRecord`、无完整文件；仍显示「仅云端」 |
| 关联的本地文件被用户删除 | 清除或标记无效 `SyncRecord`；若云端仍在，恢复显示「仅云端」 |
| 云端已删、本地仍在 | 本地显示 **未同步** 或「仅本地」（与现有回收站策略一致） |
| 共享照片（`share=1`） | 下载后 `shared` 标记保留，仍只 1 条 |
| 多选批量下载 | 每张独立满足 AC-01；进度可合并展示 |

---

## 8. 优先级与分期

| 阶段 | 内容 | 优先级 |
|------|------|--------|
| **一期** | 下载后列表去重；`remotePath` 唯一 `SyncRecord`；修复 `isSyncedFast` 用真实 `remotePath`；刷新不重复 | **P0** |
| **二期** | 下载前 hash 检测 + 关联已有本地文件；`localUri` 列表去重 | **P0** |
| **三期** | 弱匹配提示、批量下载优化、视频 Tab 完全对齐 | **P1** |

| 指标 | 目标 |

## 10. 开发备注（供 @developer 参考，非产品强制文案）

涉及模块（Android）：

- `CloudMediaDownloadHelper` / `CloudDownloadRunner` — 下载前检查、绑定唯一性
- `SyncStatusHelper` — 同步判定改用 `SyncRecord.remotePath` / `fileHash`
- `MediaTabFragment` — 列表 `remotePath` + `localUri` 去重
- `MediaScanner.buildRemotePath` — 降低假路径误判权重
- `SyncRecordDao` — 按 `remotePath` 查询/作废旧记录

服务端 **无需改动**；以现有 `relativePath` + `sha256`（sync-index）为准。
