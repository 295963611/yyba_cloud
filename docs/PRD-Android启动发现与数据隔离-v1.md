## 1. 需求背景

### 1.1 用户痛点

| 痛点 | 描述 |
|------|------|
| **启动慢、总在「发现服务器」** | 已保存过 IP/端口且服务器正常时，App 仍每次做约 5 秒的局域网扫描；登录页与主页还可能各扫一次 |
| **担心连错服务器** | 局域网自动发现仅校验健康检查接口，单台服务器时会静默覆盖已保存地址，存在误连风险 |
| **换账号/换服务器后数据混乱** | 云端索引已有环境隔离，但上传任务、部分缓存未完全清理，可能出现「上一个环境的数据残留」 |
| **已登录却连不上** | 本地有 token 时直接进主页，不校验 token 是否仍有效，用户看到旧数据或频繁报错 |
| **地址明文风险** | 自动发现 mDNS 与 prefs 均可能暴露 IP/端口；需 Discovery Key 统一加密（见关联 PRD） |

### 1.2 核心诉求（一句话）

> **先连上次成功的服务器，不通再发现；换环境就干净隔离，别串号。**

### 1.3 竞品对标

| 产品 | 连接策略 | 多环境数据 |
|------|----------|------------|
| **Synology DS file / QNAP** | 优先上次 NAS 地址，失败再搜索局域网 | 按 NAS/账号切换，本地缓存随环境更新 |
| **百度网盘 / 阿里云盘** | 固定云端域名，无 LAN 发现 | 单账号云端数据，切换账号清空本地 |
| **Dropbox / OneDrive** | 固定域名 + OAuth | 切换账号重新同步 |

**本产品取向**：对标 **家庭 NAS 助手**——记住上次成功的家庭服务器，mDNS 仅作兜底；数据隔离采用「切换环境 → 清空相关本地数据 → 拉新」，不做多环境本地长期并存。

### 1.4 现状问题摘要（评审结论）

**自动发现**

- 启动路径：已登录用户常经历 **LoginActivity + MainActivity 两次** mDNS 扫描（各约 5 秒）
- 有保存地址时仍默认扫描，未先做连通性探测
- 发现到 **1 台** 服务器时 **静默覆盖** 已保存 IP/端口
- 发现到 **多台** 且后台路径时取「第一台」，顺序不确定
- 信任模型：HTTP + `/api/health` 字段匹配，无配对码/指纹
- 并发发现时第二次请求被丢弃，行为不稳定
- 服务器地址 prefs 可能为 **明文或旧版 EncryptedSharedPreferences**；需改为 **Discovery Key 密文原样落盘**（见 `PRD-局域网发现传输加密-v1.md`）

**数据隔离**

- 已有 `EnvironmentIndexGuard`：环境 Key = `服务器 URL | 用户名`，变化时清空 `cloud_index`、`sync_records` 及内存索引
- **未清理**：`upload_tasks`、部分图片缓存；登出时亦未完全清空图片缓存
- Room 表无环境字段，依赖「切换时清空」而非「按环境分区存储」

## 2. 产品目标

### 2.1 目标

1. **启动更快**：有有效保存地址且服务器可达时，**跳过 mDNS**，用户 2 秒内进入可用状态。
2. **发现更稳**：同一启动流程 **只扫描一次**；失败再发现；减少无效 LAN 流量。
3. **连接更可信**：避免静默覆盖用户已确认的服务器地址；降低误连与劫持风险。
4. **隔离更完整**：切换服务器或账号时，本地云端索引、同步映射、**上传任务及缓存**一并清理，再拉取当前环境数据。
5. **登录态更可靠**：自动进入主页前，**轻量校验 token** 是否仍有效。
6. **发现地址密文落盘**：自动发现得到的 **密文 endpoint** 原样写入 prefs；**不存明文** host/port；解密仅在内存中进行（KEY 方案见关联 PRD **B1**）。

### 2.2 非目标（本期不做）

- 公网 HTTPS / 证书固定（另立「公网访问安全」需求）
- **配对码 / 二维码配对（B2）** — 产品选用 **B1 双端固定 KEY**，零配对
- Room 多环境分区长期并存（切换账号仍保留其他环境离线数据）
- 防 APK 逆向级安全（家庭产品不承诺 KEY 不可提取）

## 4. 功能定义

### 4.1 启动连接策略（P0）

**原则**：`记住上次 → 快连 → 失败再发现`

| 步骤 | 条件 | 行为 |
|------|------|------|
| 1 | 读取已保存 `serverUrl`（host + port） | 若无保存地址 → 进入 mDNS 发现（若开启自动发现） |
| 2 | 有保存地址 | 调用 `GET /api/health`，超时 **2 秒**（可配置） |
| 3 | health **成功** | **跳过 mDNS**，直接使用保存地址；已登录则继续进主页流程 |
| 4 | health **失败** | 若开启自动发现 → 发起 **一次** mDNS 扫描；否则提示检查网络或手动修改地址 |
| 5 | 发现结果 | 沿用现有逻辑（0/1/多台的展示与选择），但受 4.2 约束 |

**与现网差异**

| 项 | 现网 | 新行为 |
|----|------|--------|
| 有保存地址 | 仍扫描 | 先 health，成功则不扫 |
| 启动扫描次数 | Login + Main 可能各 1 次 | **整次冷启动最多 1 次** mDNS |
| 已登录进主页 | 有 token 即进 | 增加 token 有效性校验（见 4.4） |

### 4.2 自动发现安全与交互（P1）

| 规则 | 说明 |
|------|------|
| **禁止静默覆盖** | 用户**已有**保存的服务器地址时，发现到 1 台也 **不自动覆盖**，除非：用户从未保存过地址，或 health 已证明保存地址不可用且用户确认切换 |
| **多台服务器** | 前台场景弹选择器（保持）；后台/自动路径 **不** 静默选第一台，应保留原地址并提示「发现多台，请到设置选择」 |
| **发现结果展示** | 设置页「重新发现」、登录页首次配置仍可用现有选择器 |
| **HTTP 说明** | 产品说明中明确：家庭局域网为 HTTP；公共 Wi‑Fi 场景建议手动确认服务器 |

### 4.3 数据隔离策略（P0）

**产品决策**：采用 **方案 A — 切换环境即清空相关本地数据，再拉取当前环境**，不做多环境本地长期并存。

**环境 Key 定义**（沿用现网）：

```
environment_key = serverUrl + "|" + username
```

**触发清空的时机**

| 时机 | 是否清空 |
|------|----------|
| 登录成功，且 environment_key 与上次不同 | **是** |
| 进入主页前，`EnvironmentIndexGuard` 检测到 key 变化 | **是** |
| 设置页修改服务器地址或切换账号后保存 | **是** |
| 同一 environment_key 再次登录 | **否**（保留本地索引，按需刷新） |
| 用户登出 | **是**（全量清理，含 prefs） |

**须清空的数据范围**

| 数据 | 清空 | 说明 |
|------|------|------|
| `cloud_index`（云端文件索引） | ✅ | 现网已支持 |
| `sync_records`（本地↔云端映射） | ✅ | 现网已支持 |
| `upload_tasks`（未完成/已完成上传） | ✅ | **本期新增** |
| 内存索引缓存（ServerSyncCache 等） | ✅ | 现网已支持 |
| 缩略图 / 云端图片加载缓存 | ✅ | **本期新增** |
| 家庭 Tab 预取缓存 | ✅ | 现网已支持 |
| 用户 token / 服务器 prefs | 仅 **登出** 时清 | 切换账号时更新 token，不清 server 地址 |

**用户提示（P1）**

环境切换执行清空时，展示非阻塞提示：

> 已切换服务器或账号，正在加载新环境数据…

避免用户误以为「文件丢了」。

### 4.4 登录态校验（P1）

| 场景 | 行为 |
|------|------|
| 本地有 token，准备自动进主页 | 在 health 通过后，调用轻量接口校验 token（如获取当前用户信息） |
| 校验成功 | 进入 MainActivity |
| 校验失败（401/403） | **立即清除 token**，停止一切后台同步/上传，停留登录页并提示「登录已过期，请重新登录」 |
| 校验失败（纯网络错误） | **保留 token**，提示检查网络，不触发上传 |
| **登录页可见期间** | **禁止**启动 SyncWorker / SyncForegroundService / 任何上传任务（无论本地是否残留 token） |
| 任意 API 收到 401/403 | **立即清除 token** 并停止后台同步（与登出后的上传行为一致） |
| 用户手动登录 | 保持现网逻辑 |

### 4.5 设置与手动发现（保持 + 微调）

| 项 | 说明 |
|----|------|
| 「自动发现服务器」开关 | 保持；关闭后仅使用手动填写地址 + health |
| 「重新发现」按钮 | 保持；不受「启动先 health」限制，用户主动触发 |
| 服务器地址显示 | 首页/登录页展示当前使用的地址；发现失败时引导去设置 |

### 4.6 服务器地址密文存储（P1）

**产品决策（B1）**：启动器与 Android **内置相同的固定 Discovery Key**。发现链路传输 **密文**；Android **原样落盘**，不再用 Android Keystore 对地址二次加密。细则见 **`PRD-局域网发现传输加密-v1.md`**。

#### 4.6.1 存储什么

| 字段 | 存储内容 |
|------|----------|
| `server_endpoint_cipher` | mDNS TXT `ep` 或手动加密后的 Base64 **密文** |
| `token` / `username` | EncryptedSharedPreferences（**不变**） |
| ~~`server_host` / `server_port`~~ | **不再写入明文** |

#### 4.6.2 流程摘要

```
mDNS TXT ep=密文
  → Android 解密(DiscoveryKey) → health
  → ep 原样写入 prefs
  → API 时读 cipher 解密到内存
```

手动填 IP：输入明文 → 同 KEY 加密 → 写入 `server_endpoint_cipher`。

#### 4.6.3 与旧版差异

| 旧理解（v1.1，已作废） | 现定稿（v1.2） |
|------------------------|----------------|
| Android 安装随机 KEY | **双端固定 Discovery Key（B1）** |
| mDNS 明文 + 本机 AES 重加密 | **传输密文 + 原样落盘** |
| 需 B2 配对才能传密文 | **不需要配对** |

## 5. 用户操作路径（User Journey）

### 路径 A：日常打开（服务器正常，已登录）

```
打开 App
  → 读取保存地址 → health 成功（<2s）
  → 跳过 mDNS → 校验 token 有效
  → 进入首页（沿用本地索引或后台刷新）
```

### 路径 B：服务器关机或换网络

```
打开 App
  → health 失败
  → 自动发现（最多 1 次，约 5s）
  → [0 台] 提示检查网络，保留原地址
  → [1 台] 若从未保存过则写入；若已有地址则询问是否切换
  → [多台] 弹选择器（登录/设置）或提示去设置选择
```

### 路径 C：切换账号

```
登录页输入新账号 → 登录成功
  → environment_key 变化
  → 清空索引/同步/上传任务/缓存
  → 提示「正在加载新环境数据…」
  → 进入首页，拉取新账号云端数据
```

### 路径 D：切换服务器（设置页修改 IP/端口）

```
设置 → 修改服务器 → 保存
  → health 校验新地址
  → environment_key 变化（URL 部分变）
  → 执行与路径 C 相同的本地清理
  → 若 token 仍有效且属于新服务器上同一账号则继续；否则要求重新登录
```

### 路径 E：登出

```
设置 → 退出登录
  → 清空全部本地业务数据 + prefs
  → 回到登录页
```

## 6. 验收标准（Acceptance Criteria）

### 6.1 启动与发现

#### AC-01 有地址且可达时跳过发现（P0）

- **Given** 已保存有效 serverUrl，且 `/api/health` 返回正常
- **When** 用户冷启动 App（已登录或未登录）
- **Then** **不发起** mDNS 扫描；从启动到进入登录页/主页准备就绪 **≤ 2 秒**（不含后续业务拉取）

#### AC-02 有地址不可达时再发现（P0）

- **Given** 已保存 serverUrl，但 health 失败
- **When** 用户冷启动且「自动发现」开启
- **Then** 发起 **一次** mDNS；发现完成后更新 UI；整次启动 **不超过一次** 扫描

#### AC-03 单次启动不重复扫描（P0）

- **Given** 已登录用户冷启动
- **When** 从 LoginActivity 进入 MainActivity
- **Then** 全路径 mDNS **最多 1 次**（health 失败后的那一次）

#### AC-04 不静默覆盖已有地址（P1）

- **Given** 用户此前已保存并使用过服务器 A
- **When** 自动发现仅找到服务器 B
- **Then** **不** 自动将 prefs 改为 B；提示用户确认或前往设置选择

#### AC-05 关闭自动发现（P1）

- **Given** 用户关闭「自动发现」
- **When** health 失败
- **Then** 不扫描；提示检查网络或手动修改地址

### 6.2 数据隔离

#### AC-06 切换账号清空本地业务数据（P0）

- **Given** 用户 A 在服务器 S 上已产生 cloud_index、sync_records、upload_tasks
- **When** 用户 B 在同一服务器 S 登录成功
- **Then** A 的索引、映射、上传任务 **均不可见**；B 的数据来自服务器拉取；无串号列表项

#### AC-07 切换服务器清空本地业务数据（P0）

- **Given** 用户 A 在服务器 S1 上有本地索引与未完成上传
- **When** 用户将服务器改为 S2 并保存（或登录 S2）
- **Then** S1 的 cloud_index、sync_records、upload_tasks **已清空**；界面仅展示 S2 环境数据

#### AC-08 同环境不清空（P0）

- **Given** environment_key 未变
- **When** 用户杀进程后重新打开 App 并自动登录
- **Then** 本地 cloud_index、sync_records **保留**（可按 TTL 后台刷新）

#### AC-09 登出全清（P0）

- **When** 用户点击退出登录
- **Then** token、服务器 prefs、Room 业务表、相关缓存 **全部清空**

#### AC-10 环境切换提示（P1）

- **When** 因账号或服务器变化触发本地清空
- **Then** 用户看到「正在加载新环境数据…」类提示；完成后进入正常首页

### 6.3 登录态

#### AC-11 Token 校验（P1）

- **Given** 本地 token 存在但服务端已注销/过期
- **When** 用户打开 App 走自动进主页路径
- **Then** 不进入主页；清除 token；登录页提示重新登录

### 6.4 地址密文存储（Discovery Key · B1）

#### AC-12 发现密文原样落盘（P1）

- **Given** mDNS 广播 TXT `ep` 为密文，且 health 校验通过
- **When** 系统保存服务器地址
- **Then** prefs 中 `server_endpoint_cipher` **与广播 `ep` 一致**；**无**明文 host/port/url

#### AC-13  prefs 无明文地址（P1）

- **Given** 用户通过自动发现或手动填写保存地址
- **When** 检查本地 prefs / adb backup
- **Then** **不得**出现明文 IP/端口；手动保存亦为 cipher；token 仍 EncryptedSharedPreferences

## 7. 边界与异常

| 场景 | 期望 |
|------|------|
| health 超时但 mDNS 找到同一台 | 可提示「连接不稳定」；地址不变 |
| health 与 mDNS 找到不同机器 | 不自动切换；用户确认 |
| 切换环境时有正在上传的任务 | **取消或清空** 旧环境 upload_tasks，不在新环境继续传 |
| 切换环境时「仅云端」已下载文件 | 本地媒体文件 **保留**（属于手机存储）；仅清理 **云端索引与映射** |
| 无网络 | health 失败；不无限重试；明确提示 |
| 并发点击登录与发现 | 不产生两次并行扫描；UI 不卡死 |
| 家庭 Tab 预取中切换账号 | 预取中断；缓存清空；不展示旧账号分享内容 |
| 加密组件初始化失败 | 仅影响 **token** ESP；地址为 cipher 不受影响 |
| 卸载重装 App | 需重新发现或手动填 IP；Discovery Key 仍在 APK 内 |
| 旧版明文 prefs | 首次启动迁移为 cipher（见传输加密 PRD） |

## 8. 优先级与分期

| 阶段 | 内容 | 优先级 |
|------|------|--------|
| **一期** | 启动先 health、失败再发现；单次启动只扫描一次；切换环境清空 upload_tasks + 图片缓存；切换提示文案 | **P0** |
| **二期** | 禁止静默覆盖；token 校验；多台后台不静默选第一台；**Discovery Key 密文发现+落盘（B1，见传输加密 PRD）** | **P1** |
| **三期** | 设置页「清除本机缓存」；Room environment_key 预留；HMAC 验签（可选） | **P2** |

---

## 9. 对现有行为的影响说明

| 变更点 | 用户感知 |
|--------|----------|
| 启动先 health | **打开更快**；多数家庭日常使用不再看到长时间「正在发现」 |
| 减少 mDNS 次数 | 局域网更安静；部分机型发现失败率可能下降（少一次并发） |
| 切换环境清 upload_tasks | 换号后 **不会** 把旧账号文件误传到新环境 |
| 不静默改地址 | 需多一次确认；**更安全** |
| Token 校验 | 过期用户需重新登录一次；避免假在线 |
| 地址密文 | 传输与手机均无明文 IP；零配对 |

## 10. 开发备注（供 @developer，非用户文案）

- 启动编排：`LoginActivity`、`MainActivity` 统一经 **单一连接协调器**（建议新建 `ServerConnectCoordinator`），避免 Login/Main 各调一次 `ServerDiscoveryManager`
- health：复用 `NsdServerDiscovery.verifyHealth()` 或等价逻辑；超时建议 2s，与发现 5s 分离
- 发现：`ServerDiscoveryManager` 并发丢弃问题需在协调器层合并回调或排队
- 隔离：扩展 `EnvironmentIndexGuard` / `ServerSyncCache.clearIndexOnlySync` → `clearEnvironmentDataSync`，增加 `UploadTaskDao` 全表清理、`CloudImageLoader.clearCache()`
- 登出：`MainActivity.logout()` 对齐调用全量清理
- Token 校验：复用现有 API（如用户信息接口）；401 走统一登出
- **地址密文**：`PrefsManager` 存 `server_endpoint_cipher`；`DiscoveryCrypto` 固定 KEY 与启动器一致；详见 `PRD-局域网发现传输加密-v1.md`
- Token：仍 EncryptedSharedPreferences
- 可选：`WifiManager.MulticastLock` 仅在真正发起 mDNS 时持有
- 关联模块：`PrefsManager`、`EnvironmentKey`、`ServerDiscoveryHelper`、`AppDatabase`
