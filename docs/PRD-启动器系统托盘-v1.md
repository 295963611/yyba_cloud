# 悠悠爸家庭云盘 · 启动器系统托盘 PRD

| 属性 | 内容 |
|------|------|
| 文档版本 | v1.0 |
| 状态 | 需求定稿（已开发 v1） |
| 产品模块 | PC 启动器（JavaFX） |
| 关联端 | 启动器 only；Web / Android 不涉及 |
| 现状 | 点窗口关闭即停止服务并退出进程 |

---

## 1. 需求背景

### 1.1 用户痛点

家庭云盘服务器通常需要**长期在后台运行**，但当前启动器：

- 关闭窗口会**立即停止 Web 服务并退出程序**
- 任务栏始终占着一个窗口，容易被误关
- 临时查看配置后，无法「藏起来」让服务继续跑

用户期望：像网盘客户端、下载工具一样，**最小化到系统托盘**，需要时再打开管理界面；在托盘上就能启停服务。

### 1.2 核心诉求（一句话）

> **关窗不等于退出；托盘常驻，右键管服务。**

### 1.3 竞品对标

| 产品 | 托盘行为 | 右键菜单 |
|------|----------|----------|
| **Synology Assistant** | 关窗缩到托盘，服务继续 | 打开、退出等 |
| **OneDrive / Dropbox** | 后台同步，托盘控制 | 暂停、设置、退出 |
| **qBittorrent** | 关窗最小化到托盘 | 启动/暂停、打开、退出 |
| **百度网盘 PC 版** | 托盘 + 右键菜单 | 打开主界面、退出 |

**本产品取向**：对标 **NAS 助手 + 网盘客户端**——家庭服务器**默认后台常驻**，托盘是日常控制入口。

---

## 2. 产品目标

### 2.1 目标

1. 用户可将启动器**最小化到系统托盘**，Web 服务可继续运行。
2. 托盘图标**右键**弹出菜单：**启动服务**、**停止服务**、**退出**。
3. 关闭主窗口（点 ×）时**默认缩到托盘**，不停止服务、不退出进程。
4. 托盘菜单与主界面「启动服务 / 停止服务」**状态一致**（该灰的灰、该禁用的禁用）。

### 2.2 非目标（本期不做）

- 开机自启动（另立需求）
- 托盘气泡通知（上传完成、磁盘满等）
- macOS 菜单栏形态适配（本期以 **Windows 托盘** 为准）
- 托盘图标按流量/连接数实时动画

## 3. 用户故事

| ID | 角色 | 故事 | 优先级 |
|----|------|------|--------|
| US-01 | 家长 | 我配置好云盘后关掉管理窗口，服务仍在跑，家人能继续用手机访问 | **P0** |
| US-02 | 家长 | 我在托盘图标上右键，能快速停止或启动服务，不用再打开大窗口 | **P0** |
| US-03 | 家长 | 我想彻底关掉云盘时，从托盘选「退出」，程序和服务都结束 | **P0** |

| US-05 | 家长 | 我双击托盘图标，能重新打开管理界面 | **P1** |
| US-06 | 家长 | 托盘图标能区分「服务运行中 / 已停止」 | **P1** |

## 4. 功能定义

### 4.1 托盘图标

| 项 | 说明 |
|----|------|
| 图标 | 使用现有品牌 Logo（48×48 或专用 16×16 托盘图） |
| 提示文字（Tooltip） | 运行中：`悠悠爸家庭云盘 - 运行中 (http://IP:端口)`；已停止：`悠悠爸家庭云盘 - 已停止` |
| 显示时机 | 启动器进程启动后即显示托盘图标（主窗口显示前后均可） |

### 4.2 关窗行为（重要变更）

| 操作 | 当前行为 | **新行为** |
|------|----------|------------|
| 点窗口 **×** | 停止服务 + 退出 | **隐藏主窗口，缩到托盘；服务保持原状态** |
| 托盘菜单 **退出** | — | 停止服务 + 退出进程（见 4.4） |
| 任务栏最小化 | 窗口最小化 | 可选 P1：最小化也进托盘（与关窗一致） |

> **产品原则**：家庭 NAS 场景下，误点 × 不应导致全家断网。

### 4.3 右键菜单

| 菜单项 | 说明 | 可用条件 |
|--------|------|----------|
| **打开管理界面** | 显示主窗口并置前 | 始终可用（P0 建议纳入，否则用户难以找回窗口） |
| **启动服务** | 等同主界面「启动服务」 | 仅当服务**未运行**时可点 |
| **停止服务** | 等同主界面「停止服务」 | 仅当服务**运行中**时可点 |
| **退出** | 彻底退出启动器 | 始终可用 |

菜单顺序建议：

```
打开管理界面
─────────────
启动服务
停止服务
─────────────
退出
```

### 4.4 退出确认

| 场景 | 行为 |
|------|------|
| 服务**已停止** | 直接退出 |
| 服务**运行中** | 弹窗确认：「退出将停止家庭云盘服务，家人将无法访问。确定退出？」→ 确定则停服务并退出；取消则留在托盘 |

### 4.5 与主界面联动

- 主界面点击「启动服务 / 停止服务」后，托盘菜单项启用状态**立即同步**。
- 托盘执行启停后，若主窗口已打开，主界面状态标签、按钮、访问地址**同步刷新**（与现有 3 秒轮询一致或即时刷新）。
- 托盘启停逻辑**复用**现有 `onStartServer` / `onStopServer`，不另写一套业务规则。

### 4.6 左键行为（P1）

| 操作 | 行为 |
|------|------|
| **双击**托盘图标 | 打开/显示主管理窗口 |
| 单击 | 本期不做（避免误触）；若实现则等同「打开管理界面」 |

## 5. 用户操作路径（User Journey）

### 路径 A：日常后台运行

```
启动启动器 → 启动服务 → 点窗口 × 
  → 窗口消失，托盘保留图标（Tooltip 显示运行中）
  → 家人手机/Web 仍可访问
```

### 路径 B：托盘快速停服

```
托盘图标右键 → 停止服务 
  → 服务停止，Tooltip 变为「已停止」
  → 「启动服务」变为可点，「停止服务」变灰
```

### 路径 C：彻底退出

```
托盘右键 → 退出 
  → [若服务运行中] 确认对话框 
  → 停止服务 → 托盘图标消失 → 进程结束
```

### 路径 D：找回管理界面

```
双击托盘图标（或右键「打开管理界面」）
  → 主窗口重新显示，状态与托盘一致
```

## 6. 验收标准（Acceptance Criteria）

### AC-01 关窗缩托盘（P0）

- **Given** 服务正在运行
- **When** 用户点击主窗口 ×
- **Then** 主窗口隐藏；托盘图标仍在；服务**仍在运行**；家人仍可访问 Web/API

### AC-02 托盘启动服务（P0）

- **Given** 服务已停止，主窗口可隐藏
- **When** 托盘右键 → 启动服务
- **Then** 服务启动成功；Tooltip 显示运行中与访问地址；菜单「启动服务」禁用、「停止服务」可用

### AC-03 托盘停止服务（P0）

- **Given** 服务正在运行
- **When** 托盘右键 → 停止服务
- **Then** 服务停止；家人无法访问；菜单状态反转

### AC-04 托盘退出（P0）

- **When** 托盘右键 → 退出（服务运行中需确认）
- **Then** 服务停止、托盘图标消失、进程结束；再次访问需重新启动启动器

### AC-05 菜单与主界面一致（P0）

- **When** 在主界面或托盘任一入口启停服务
- **Then** 另一入口的按钮/菜单启用状态在 1 秒内一致

### AC-06 打开管理界面（P0）

- **Given** 主窗口已隐藏
- **When** 托盘「打开管理界面」或双击图标（P1）
- **Then** 主窗口显示并置前，内容与当前服务状态一致

### AC-07 无托盘环境降级（P1）

- **Given** 系统不支持系统托盘（极少见）
- **Then** 保持现有行为或提示「无法使用托盘，关闭窗口将退出」；不崩溃

## 7. 边界与异常

| 场景 | 期望 |
|------|------|
| 重复点「启动服务」 | 提示「服务已在运行中」，与不托盘时一致 |
| 存储目录未配置就启动 | 与现有一致，启动失败并提示，托盘菜单状态回滚 |
| 端口占用 | 启动失败弹窗，服务保持停止 |
| 用户管理 Tab 操作中 | 托盘停服不影响已打开窗口的数据；停服后 Web API 不可用 |
| 多显示器 / 远程桌面 | 托盘图标正常显示在系统通知区域 |
| 进程被任务管理器结束 | 服务随进程结束（与现有一致） |

## 8. 优先级与分期

| 阶段 | 内容 | 优先级 |
|------|------|--------|
| **一期** | 托盘图标；关窗缩托盘；右键菜单（打开、启停、退出）；退出确认；与主界面状态同步 | **P0** |
| **二期** | 双击打开；最小化也进托盘；托盘图标运行/停止两态 | **P1** |
| **三期** | 开机自启、托盘气泡通知 | **P2** |

## 9. 对现有行为的影响说明

| 变更点 | 影响 |
|--------|------|
| 关窗不再退出 | **体验提升**；长期运行更符合家庭服务器场景 |
| 唯一退出入口改为托盘「退出」 | 需在首次关窗或 README 中提示用户 |
| `onCloseRequest` 逻辑 | 开发需改为 `hide()` + 托盘，而非 `onStopServer()` + `Platform.exit()` |

## 10. 开发备注（供 @developer，非用户文案）

- 模块：`LauncherApp`、`MainController`；新增 `TrayService` / `SystemTrayManager` 等
- JavaFX：`java.awt.SystemTray` + `TrayIcon` + `PopupMenu`（需在 FX 线程外注意 EDT）
- 图标资源：`/images/logo/48x48.png` 或单独 `tray-16.png`
- 关窗：`stage.setOnCloseRequest` → `e.consume()` + `stage.hide()`
- 退出：统一走 `shutdown()`，先 `onStopServer()` 再 `Platform.exit()`
- 与 `WebServerLifecycleService`、`MdnsRegistrar` 现有启停链路复用
