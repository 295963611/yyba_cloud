## 1. 相册滑动「闪一下」

### 1.1 用户现象

相册（图片 Tab）手指滑动后松手，列表会 **莫名闪屏/闪一下**（缩略图先变占位图再恢复）。

### 1.2 原因分析（客户端）

当前实现逻辑：

1. 滑动时 `MediaListAdapter.setScrollPaused(true)`，暂停缩略图加载并占用全局 `ThumbBitmapCache.paused`。
2. **滑动结束（IDLE）** 时调用 `adapter.refreshVisibleThumbnails()`。
3. 该方法对 **当前可见的每一行** 执行 `notifyItemChanged(i)`，整行重新 `bind`。
4. 重新绑定时 `ThumbnailLoader` 会先设 **占位图**（`ic_menu_gallery`），再异步加载 → 肉眼可见 **闪一下**。

**结论**：属于 **客户端体验问题**，不是服务端数据问题。滑动停止后的「全量刷新可见项」策略过于粗暴。

### 1.3 产品建议（修复方向，@developer）

| 优先级 | 建议 | 验收标准 |
|--------|------|----------|
| P0 | 滑动结束后 **不要** 对可见项全量 `notifyItemChanged`；改为仅对未加载成功的项补载，或 `notifyItemChanged(i, payload)` 只刷新 `ivThumb` | 慢滑相册 10 次，可见格无整行闪白/闪占位 |
| P0 | `refreshVisibleThumbnails` 内直接调 `ThumbnailLoader.load`，不触发整行 rebind | 同上 |
| P1 | 滚动暂停时不要清空已显示 bitmap（仅暂停新任务） | 滑动过程中已出图的不变占位 |

## 2. 视频里「不存在的云端视频」一直展示、无法播放

### 2.1 用户现象

「我的视频」中出现一条 **仅云端** 条目（云端标识），点击无法播放；文件实际已不存在。

### 2.2 原因分析（数据与链路）

**展示来源（手机「我的」视频 Tab）**：

- 本地 `videos/` 扫描 + **相册 API** `listAlbumPhotos(VIDEO)` 返回的云端项（`cloudOnly` 行）。
- 本地 `cloud_index`（sync-index）用于同步状态，视频列表以 **服务端 DB + album API** 为主。

**播放**：请求 `/media/file?path=` → 服务端 `getFileResource` 要求 **磁盘上真实存在** 文件。

**典型根因：数据库有记录，磁盘无文件（幽灵元数据）**

| 场景 | 说明 |
|------|------|
| 磁盘手动删除 | 用户在服务器上删了文件，DB 未删 |
| 回收站/删除不完整 | 仅删磁盘或仅标 DB（异常路径） |
| 上传失败残留 | 会话异常留下 DB 记录无落盘 |
| 客户端缓存 | 本地 `cloud_index` 陈旧（较少见：album API 仍返回则说明服务端 DB 仍有） |

**服务端现状**：

- `reconcileDisk` / `DiskIndexService`：**只补录**「磁盘有、DB 无」，**不清理**「DB 有、磁盘无」。
- `listAlbumPhotos`：查 `files` 表 `deleted_at IS NULL`，**不校验**磁盘是否存在。
- 已有定时任务：`TrashCleanupService`（回收站过期）、上传会话清理；**无**「幽灵文件记录」定时清理。

**结论**：多半是 **服务端元数据与磁盘不一致**；客户端按 API 展示是符合逻辑的，播放失败是预期结果。

### 2.3 产品建议

#### 客户端（短期，P0）

| 项 | 说明 | 验收标准 |
|----|------|----------|
| 播放前/播放失败处理 | 无法播放时 Toast 明确提示「云端文件不存在」 | 用户知道是数据问题而非网络 |
| 自动剔除（可选 P0） | 播放 404/文件不存在时，从当前列表移除并 `removePaths` 本地索引 | 幽灵项不再反复出现 |
| 下拉刷新 | 视频 Tab 强制 `refreshSync` + 重拉列表 | 服务端修完后客户端可恢复 |

#### 服务端（中期，P0～P1）

| 项 | 说明 | 验收标准 |
|----|------|----------|
| 列表接口校验（推荐 P0） | `listAlbumPhotos` / sync-index **返回前**校验磁盘存在；不存在则跳过或标 `missing` | 列表不出现不可播幽灵项 |
| 孤儿清理任务（P1） | 定时扫描：DB 有效记录但磁盘不存在 → 标删除或移回收站/硬删元数据 | 任务日志可看到清理数量 |
| 手动「校验媒体库」（P1） | Web 管理页一键「磁盘与数据库对账」 | 管理员可修复历史脏数据 |

## 3. 服务端是否需要定时清理「不存在文件」的数据？

### 3.1 产品结论：**需要，但分类型**

| 数据类型 | 是否定时清理 | 说明 |
|----------|--------------|------|
| 回收站过期文件 | **已有** | `TrashCleanupService` |
| 上传临时分片/过期会话 | **已有** | `UploadService.cleanupExpiredSessions` |
| **DB 有记录、磁盘无文件（孤儿）** | **建议新增 P1** | 当前缺失，是幽灵视频主因 |
| **磁盘有文件、DB 无记录** | **已有补录** | `reconcileDisk`，不是删除 |
| 客户端 `cloud_index` | **客户端** | 依赖 sync-index `removedPaths` + 全量刷新 |

### 3.2 建议的「媒体库对账」任务（P1）

**频率**：每日低峰一次（可配置，默认 03:00）。

**规则**：

1. 遍历 `files` 表 `deleted_at IS NULL` 且路径在 `photos/`、`videos/`、`audio/` 等媒资目录。
2. 若磁盘（含回收站 `.trash` 内）均不存在 → 视为孤儿。
3. 处理策略（产品默认）：**软删除进回收站**（与用户「删除」一致，可恢复）；若业务要求可直接硬删元数据（需二次确认）。

**不做**：未经对账直接删用户 `media/` 影院目录（家庭影院上线后单独策略）。

### 3.3 sync-index 增量

删除/清理孤儿后，应产生 **增量 removedPaths**，Android `ServerSyncCache` 已支持合并删除。

## 4. 验收标准汇总（给测试）

### 相册闪屏

- [ ] 相册快速上下滑动 20 次，无明显整格闪白
- [ ] 滑动停止后缩略图保持，不先变灰再恢复

### 幽灵云端视频

- [ ] 服务端删除磁盘文件并执行对账后，视频列表不再出现该项
- [ ] 若暂时仍存在，点击播放有明确错误提示，且刷新后消失
- [ ] sync-index 增量含该 `relative_path` 的 removed

### 定时清理

- [ ] 配置对账任务后，人工制造「DB 有、盘无」记录，次日被清理或从列表消失
- [ ] Web 可查看最近一次对账结果（清理数、失败数）

## 5. 优先级建议

| 优先级 | 事项 | 负责 |
|--------|------|------|
| P0 | 修复相册滑动 `refreshVisibleThumbnails` 闪屏 | Android |
| P0 | 列表接口过滤磁盘不存在项 **或** 播放失败剔除 + 提示 | Android + 服务端 |
| P1 | 服务端定时/手动「媒体库对账」清理孤儿 DB | 服务端 |
| P2 | Web 对账报告页 | Web |
